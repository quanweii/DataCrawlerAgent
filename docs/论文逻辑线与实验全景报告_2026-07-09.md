## 二、论文逻辑线 (Story Arc)

### 开篇 (§1 Intro, 1.5p)

**Hook**: "When should we use a GNN instead of an MLP on real-world multimodal data?"

现有 MAG benchmark (OpenMAG, MAGB) **无法诚实回答**这个问题，因为:
1. 它们的同质性不是受控变量 — 数据集是散点，不是一根线上的刻度
2. 无法区分「GNN 的增益来自图结构还是来自标签泄露」
3. 没有控制特征质量 → GNN-MLP gap 被标签泄露 + 编码器族同时混淆

**我们的回答**: 构建了 4 域受控实验网格 (steam→tmdb→wikiart + arxiv, homophily 0.24→0.93)，通过 leak-free 协议消除结构泄露，用 steering 实验固定特征只变边 → 找到三因子公式:

> **GNN-MLP gap ≈ f(homophily, feature predictiveness) — with homophily being necessary but NOT sufficient.**

### 主体 (§3-5 Methods + Dataset)

**§3 The MAG-Bench Datasets** (2p) — 为什么选这 4 个域 = 同质性设计逻辑 + 统计表 + 与 OpenMAG 对比

**§4 Dataset Construction Framework** (2p) — YAML 配置系统 (可复现性机制) + 多智能体编排 (对抗性质量闭环) + Claude Code Skill (可用性)。Agent 定位 = "how we built it，not why it's novel"

**§5 Benchmark Design** (1.5p) — Leak-free 协议 + NC 剪枝切分 + LP 三档负采样 + E1 steering 因果框架

### 实验发现 (§6 Experiments, 4p) — 论文核心

| 实验 | 问题 | 发现 | 对应贡献 |
|---|---|---|---|
| **E1 Steering** | 同质性 vs GNN 增益的因果效应? | MLP 跨关系 spread=0.000 (恒定对照), GCN F1 随同质性 0.22→0.96 单调翻转 | C1 核心 |
| **E2 Modality×Structure** | 模态重要性是否与图结构交互? | wikiart image 主导: MLP image=0.655, GCN image=0.806 (GNN 增益 +0.151); text MLP=0.948 但加图像反降 | C1 核心 |
| **E3 LP Desaturation** | 随机负采样如何虚高 LP? | wikiart MLP random AUC 0.972 → hard AUC 0.780 (Δ=0.192), 同质性越高 Δ 越大 | C1 核心 |
| **E4 Encoder Sensitivity** | MLP≥GNN 是否仅对 CLIP 成立? | CLIP-large/CLIP-base/SigLIP 三族: MLP≥GNN 稳健; encoder 族间差异远小于域/模态差异 | C1 鲁棒性 |
| **E5 Cross-Domain Transfer** | 跨域知识可迁移吗? | 负结果: 6 对全负增益，迁入 wikiart 灾难 (0.918→0.35)。各域图偏置不可共享。 | C2 完整性 |
| **E6 Citation LLM Ablation** | Agent 是否有不可替代的语义能力? | fuzzy OCR 标题 LLM recall 0.714 ≫ 规则 0.000/0.286 | C3 证据 |
| **E7 Multi-Agent Quality Loop** | Multi-agent 是否是 load-bearing? | Verifier↔Builder 对抗闭环: wikiart 检测 shared_style homophily=1.0 → reprocess → 排除 → LP-ceiling 0.921→0.045 | C3 证据 |

### 收尾 (§7-8 Discussion + Conclusion, 1.5p)

- 诚实声明: agent 不做建图决策 (确定性规则建图 + 鲁棒性兜底)
- Limitation: encoder 族有限 (3 个)、规模偏小 (steam 2.8K)、仅 co-attribute 域
- 未来: 社区贡献新域 (只需 YAML)、encoder 多样性、非 co-attribute 域扩展

## 三、现有实验清单 (按贡献分组)

### 3.1 C1 (头号贡献) — Benchmark 发现

#### ✅ E1: NC Steering (已完成)
- **脚本**: `benchmark/run_steering.py`
- **结果**: `benchmark/results/steering/steering_all.json`
- **覆盖**: 3 域 (steam/tmdb/wikiart), text modality, 5 GNN 模型 per 关系子图
- **核心发现**:
  - MLP F1 **跨所有关系 subgraph bit-identical** (spread=0) → 所有差异来自图结构
  - GCN F1 **单调随同质性**: tmdb shared_actor (h=0.22) GCN F1=0.225 → steam same_developer (h=0.82) GCN F1=0.568 → wikiart shared_style (h=1.0) GCN F1=0.958
  - wikiart shared_style (h=1.0): GAT 0.991, GraphSAGE 0.992 — 构建退化铁证: 边即标签 → GNN 碾碎 MLP
  - steam 单域内即完成 GNN-MLP 穿越 (shared_category h=0.44 GCN<MLP → same_developer h=0.82 GCN>MLP)

#### ✅ E1-LP: LP Steering (已完成)
- **脚本**: `benchmark/run_steering_lp.py`
- **结果**: `benchmark/results/steering/steering_lp_all.json`
- **核心发现**: LP 主要由特征-标签纠缠主导，关系旋钮影响弱于 NC。干净点: wikiart shared_style random AUC 0.998 = 基准被解出。

#### ✅ E2: Modality Ablation (已完成)
- **来源**: `benchmark/results/newdomain_nc/` 中 text / image / text+image 三列
- **覆盖**: 4 域 × 3 modality × 6 GNN × 5 seed
- **核心发现**:
  - tmdb 强文本主导: text MLP=0.696 ≫ image MLP=0.514
  - wikiart 反直觉: text MLP=0.948 > text+image MLP=0.933 (加入图像增加 MLP 噪声)
  - 但 GCN 从图像中受益巨大: wikiart image GCN=0.806 vs MLP=0.655 (Δ=+0.151)
  - 模态×结构交互成立: "用哪个模态"与"用不用结构"耦合

#### ✅ E3: LP Desaturation (已完成)
- **脚本**: `benchmark/run_newdomain_lp.py`
- **结果**: `benchmark/results/newdomain_lp/lp_{domain}_summary.json`
- **覆盖**: 4 域 × 6 模型 × 3 档负采样 (random/hard/hard_degree) × 5 seed
- **核心发现**:
  - **去饱和全域成立**: random AUC > hard AUC > hard_degree AUC，无一例外
  - **Δ(random−hard_degree) 随同质性**: wikiart (h=0.90) avg Δ=0.14 > arxiv (h=0.93) Δ=0.09 > tmdb (h=0.24) Δ=0.04 > steam (h=0.52) Δ=0.03
  - wikiart 最极端: MLP random 0.972 → hard_degree 0.743 (Δ=0.229)
  - GIN 最 "鲁棒" (Δ 最小): sum-pooling 对同质性捷径依赖更低
  - **LP+NC 联合诊断一致**: wikiart NC leak-free (MLP 0.933/GCN 0.900) 和 LP hard (GCN 0.901/MLP 0.780) 都指向同一结论

#### ✅ E4: Encoder Family Sensitivity (部分完成)
- **来源**: PAPER_THESIS_v2.md §3.3
- **覆盖**: steam + tmdb × CLIP-large/CLIP-base/SigLIP, wikiart pending
- **核心发现**:
  - MLP ≥ GNN 在三族编码器间稳健 (非 CLIP 特例)
  - SigLIP 在 steam 最优 (MLP 0.727)
  - encoder 族间差异 << 模态/域差异
- **⚠️ 缺口**: wikiart 编码未完成; 需要 ≥1 个 text-specific encoder (BGE/E5)

#### ✅ E5: Cross-Domain Transfer (已完成)
- **脚本**: `benchmark/run_newdomain_crossdomain.py` + `benchmark/run_crossdomain_ablation.py`
- **覆盖**: 4 域 pairwise, linear_probe + full_finetune
- **核心发现**: 干净负结果 — 6 对全负增益，迁入 wikiart 灾难。各域图偏置不可共享 → 支撑按域建模。

#### ✅ E6: GNN-MLP Gap Analysis (由 NC 主表直接导出)
- **来源**: `benchmark/results/newdomain_nc/` + `benchmark/results/leakage_free_nc/`
- **核心发现**:
  - tmdb (h=0.24): GCN<GAT<GCNII<GraphSAGE<MLP — GNN 崩盘
  - steam (h=0.52): MLP best (0.501 F1), GCNII close — 特征饱和
  - wikiart (h=0.90): GraphSAGE best (0.938 F1), MLP=0.858 — 结构有帮助
  - arxiv (h=0.93): 全覆盖 ~0.90, GNN≈MLP — 同质但特征已饱和
  - **二元决定**: arxiv 同质性最高但 gap 最小 (+0.009), wikiart 反而最大 (+0.080) — 是「同质性×特征可预测性」的交互，非单因子

#### ✅ E7: Within-Domain Homophily Analysis (由 Steering 直接导出)
- GCN F1 vs homophily scatter: steam 单域内 5 个关系呈现 h=0.44→0.82, GCN F1 从低于 MLP 穿越到超过 MLP
- **零点穿越 ≈ h=0.5-0.6** (steam 域内)

| **Effectiveness** | 24 模型 + 显著性 + 模态检索 + 自监督 | ✅ 6 baseline GNN + 显著性; ⚠️ 高级模型待跑; ⚠️ 缺自监督 | G3 (P1) |
| **Robustness** | 特征/标签/边噪声 + 模态缺失 | ✅ LP desaturation; ✅ cross-domain transfer; ⚠️ noise experiments runner 存在但未出表 | P2 |
| **Efficiency** | 理论复杂度 + 实测 | ⚠️ 构建墙钟有记录但未体系化 | P2 |

**总分**: 5 维度中 3 个已主要覆盖 (Necessity/Data Quality/Effectiveness 基线), 2 个部分覆盖 (Robustness/Efficiency)。对标 OpenMAG 的 benchmark 完整性, 当前覆盖约 **70%**。

## 十、给导师的汇报要点

1. **论文已从 "工具论文" 升级为 "benchmark + 工具论文"**：三大贡献的排序已从「框架→数据集→benchmark」倒置为「benchmark 发现→数据集→框架」(更匹配审稿人期待)
2. **Leak-free + steering 是该 benchmark 的护城河**：别人没有同质性受控设计，别人没有 steering 因果证据 (同一个域内同节点同特征只换边 = 无混淆变量的准实验)
3. **Multi-agent 叙述已诚实化**：不再声称 agent 做建图决策，而是对抗性质量闭环 (Verifier↔Builder reprocess loop) + 语义 wrangling (citation E2)。审稿人无法攻击 "agent 只是套壳"
4. **4 个域的同质性谱是独特资产**：0.24 (tmdb, 强异质) → 0.52 (steam, 中同质) → 0.90 (wikiart, 强同质) + 0.93 (arxiv, 近完美同质) 构成天然实验台
5. **当前缺口 = 3 天计算 + 3 天写作 = 1 周可达提交状态**：P0 = encoder 多族 + 第 5 域 (2 天计算), P1 = 高级 GNN + scatter + 打包 (1 天计算 + 3 天写作)
